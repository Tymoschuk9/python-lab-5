# Лабораторна робота №5
## Тема: Обробка помилок, файли та серіалізація

## Мета роботи
Сформувати практичні навички створення надійних Python-програм, які коректно працюють із помилками, файловими ресурсами, конфігурацією та структурованими форматами даних. Опанувати принципи EAFP, fail-fast, створення власних менеджерів контексту, механізми висхідного ланцюжка винятків (exception chaining) та атомарний запис файлів без перевантаження оперативної пам'яті за допомогою Streaming I/O.

---

## Опис алгоритму та архітектури (Варіант №3)

Для реалізації **Варіанта №3** було обрано доменну область **"Телеметрія IoT датчиків" (IoT Sensor Telemetry)**. Кожен запис містить такі поля:
- `sensor_id` (ідентифікатор сенсора)
- `timestamp` (дата та час зняття показника)
- `temperature` (температура в межах заданого діапазону)
- `humidity` (вологість в межах заданого діапазону)
- `status` (статус пристрою: `OK`, `WARNING`, `ERROR`)

### Архітектурні рішення:
1. **Зовнішня конфігурація**: Конфігурація процесу задається у файлі формату **YAML/JSON**. Для повної незалежності від зовнішніх залежностей (таких як бібліотека `PyYAML`, якої може не бути на машині перевірки) було створено кастомний парсер конфігурацій `parse_simple_yaml`.
2. **Принцип Fail-fast**: Валідація параметрів конфігурації (перевірка існування файлів, валідність діапазонів значень, сумісність форматів) виконується одразу під час ініціалізації класу `AppConfig`. Програма припиняє виконання негайно у разі виявлення помилок конфігурації.
3. **Стрімінгове читання та запис (Streaming I/O)**: Для захисту від переповнення оперативної пам'яті (при потенційному завантаженні гігабайтних логів сенсорів) читання реалізовано через **генератори** за допомогою вбудованого модуля `csv.DictReader` або зчитуванням JSON-рядків (JSON Lines) по одному рядку за ітерацію.
4. **Концепція EAFP**: Перетворення типів (наприклад, текстового поля температури на `float`) здійснюється за принципом *"Easier to Ask Forgiveness than Permission"* за допомогою блоків `try-except-else`.
5. **Атомарний запис**: Реалізовано кастомний контекстний менеджер `AtomicFileWriter` за протоколом `__enter__` / `__exit__`. Запис спочатку здійснюється в унікальний тимчасовий файл. Тільки у разі успішного завершення всього пайплайну без винятків, тимчасовий файл атомарно замінює цільовий. Це гарантує, що у разі критичної помилки на диску ніколи не залишиться напівпорожнього чи пошкодженого файлу.
6. **Політики обробки помилок (Validation Policies)**:
   - `strict` — будь-який невалідний рядок зупиняє роботу програми, цільовий файл залишається незмінним.
   - `log_and_skip` — невалідні записи записуються в логгер як попередження та просто пропускаються.
   - `force_default` — некоректні числові дані підміняються дефолтними значеннями конфігурації.

## Опис реалізованих функцій та класів

- **`ApplicationError` ... `ConfigurationError`** (Ієрархія винятків):
  Забезпечує структуровану обробку помилок. `RecordValidationError` містить додаткові атрибути `line_number` та `field` для точної ідентифікації місця помилки.
- **`AtomicFileWriter`**:
  Клас-менеджер контексту для безпечного запису файлів.
- **`execution_timer`**:
  Генераторний менеджер контексту (використовує `@contextmanager`) для заміру реального часу роботи пайплайну.
- **`AppConfig`**:
  Клас завантаження конфігурації та валідації параметрів. Забезпечує роботу принципу fail-fast.
- **`parse_simple_yaml`**:
  Парсер файлів конфігурації у форматі YAML без використання сторонніх модулів.
- **`read_csv_streaming` та `read_jsonl_streaming`**:
  Генератори для потрекового зчитування вхідних файлів даних.
- **`parse_and_validate_row`**:
  Функція парсингу та валідації окремого рядка телеметрії. Демонструє використання конструкцій `try/except/else` та висхідного ланцюга винятків (`raise RecordValidationError(...) from err`).
- **`run_pipeline`**:
  Головний контролер пайплайну, який координує всі кроки обробки та виконує експорт даних.

## Висновки

1. **Ефективність обробки помилок**: Створення власної ієрархії винятків дозволило чітко розмежувати системні проблеми (проблеми конфігурації, доступу до дисків) від бізнес-помилок (помилки валідації структури даних IoT-сенсора).
2. **Exception Chaining**: Завдяки конструкції `raise RecordValidationError(...) from err` вдалося зберегти низькорівневу інформацію про першопричину помилки (наприклад, системний виняток `ValueError` при невдалому перетворенні `"NaN_Value"` на float), що суттєво спрощує процес відладки у великих корпоративних системах.
3. **Ресурсна безпека та атомарність**: Застосування кастомного контекстного менеджера `AtomicFileWriter` дозволило реалізувати транзакційність файлового виводу. Це гарантує цілісність даних на диску навіть у разі раптового падіння процесу під час запису.
4. **Стрімінгова обробка**: Використання генераторів забезпечило стабільну роботу з мінімальним споживанням RAM незалежно від розміру вхідних логів, оскільки в один момент часу в пам'яті утримується лише один зчитаний рядок.

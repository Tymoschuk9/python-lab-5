# Лабораторна робота №5
## Тема: Обробка помилок, файли та серіалізація
## Мета роботи
Сформувати практичні навички створення надійних Python-програм, які коректно працюють із помилками, файловими ресурсами, конфігурацією та структурованими форматами даних. Опанувати механізм винятків (Exceptions), менеджерів контексту, логування та потокового вводу-виводу (Streaming I/O).

---

## Опис алгоритму та архітектури (Варіант №3)
Відповідно до **Варіанта №3**, у лабораторній роботі реалізовано **Систему імпорту, валідації та обробки показників датчиків розумного будинку (IoT Sensors Data Processor)**.

### Архітектура системи:
1. **Ієрархія винятків (Exceptions)**:
   Всі винятки наслідуються від базового класу `ApplicationError`. Створена деталізована структура класів помилок (`ConfigurationError`, `DataImportError`, `DataExportError` тощо), що дозволяє гнучко реагувати на нештатні ситуації на різних етапах пайплайну.
2. **Менеджер конфігурації (`AppConfig`)**:
   Завантажує JSON-файл налаштувань, валідує допустимі межі показників датчиків (температура, вологість) та політику обробки помилок. Реалізовано принцип **Fail-fast** — програма аварійно завершується на старті, якщо конфігурація некоректна чи відсутня.
3. **Потокові зчитувачі (`DataStreamer`)**:
   Забезпечують **Streaming I/O**. Дані з файлів CSV та JSON Lines (JSONL) зчитуються та генеруються поодинці за допомогою ключового слова `yield`, що запобігає перевантаженню оперативної пам'яті великими обсягами вхідних даних.
4. **Валідація та конвертація доменних об'єктів (`SensorDataValidator` / `SensorReading`)**:
   Здійснюють бізнес-перевірку параметрів. Використовують філософію **EAFP** для початкового парсингу та перевірки типів даних, а також **LBYL** для перевірки допустимого діапазону. При помилці створюється деталізований виняток `RecordValidationError`, який містить метадані (номер рядка, невірне поле та значення).
5. **Атомарний запис (`AtomicFileWriter`)**:
   Контекстний менеджер, який здійснює запис у тимчасовий файл. Лише у разі успішного завершення операцій він замінює оригінальний вихідний файл. Це убезпечує від пошкодження та втрати старих даних при падінні скрипта на півшляху.
6. **Головний керуючий модуль (`DataProcessingPipeline`)**:
   Об'єднує всі компоненти, виконує обробку з урахуванням конфігураційної політики помилок (`raise_on_invalid`, `log_and_skip`, `ignore_invalid`) та заміряє час виконання за допомогою кастомного менеджера контексту `execution_timer`.

---

## Опис реалізованих функцій та класів

* **`ApplicationError` ... `RecordValidationError`**: Об'єкти винятків. `RecordValidationError` додатково зберігає контекст помилки (номер рядка, ім'я поля, передане невірне значення) для спрощення діагностики.
* **`execution_timer(activity_name)`**: Декоратор-контекстний менеджер для точного вимірювання швидкодії блоку коду за допомогою `time.perf_counter()`.
* **`AtomicFileWriter`**: Реалізує протокол контекстного менеджера через методи `__enter__` та `__exit__`. Гарантує транзакційність запису на рівні файлової системи.
* **`AppConfig`**: Клас для зчитування налаштувань. Перевіряє коректність діапазонів температур та вологості на етапі ініціалізації.
* **`DataStreamer`**: Містить статичні методи-генератори `stream_csv` та `stream_jsonl` для потокового читання без повного завантаження файлу в ОЗП.
* **`SensorDataValidator`**: Валідує кожне поле структури сенсора. Здійснює перетворення типів та обробляє винятки через механізм **Exception Chaining** (`raise RecordValidationError(...) from error`).
* **`SensorReading`**: Доменний клас, що описує стан сенсора у системі, підтримує серіалізацію в стандартний словник Python через `.to_dict()`.
* **`DataProcessingPipeline`**: Головний конвеєр, що зв'язує вхідний потік читання, валідацію, обробку винятків та атомарний запис у вихідний файл.

## Результати виконання програми

При запуску демонстраційного методу `main()` виконується наступний ланцюг подій:
1. Ініціалізація тестового середовища (створюються `config.json`, `sensor_data.csv` з помилками та `sensor_data.jsonl`).
2. Успішний імпорт та валідація налаштувань.
3. Потокова обробка CSV файлу. Некоректні записи (з неправильною температурою, вологістю чи невірним форматом дати) безпечно фільтруються та логуються з вказівкою на конкретні рядки завдяки політиці `log_and_skip`.
4. Результат записується у вихідний файл `processed_output.jsonl`.
5. Потокова обробка JSONL файлу виконується аналогічно.
6. Демонструється зміна політики на `raise_on_invalid`. Програма перериває обробку при першій помилці валідації та виводить детальний ланцюжок винятків (Exception Chaining).
7. Демонструється атомарність запису: при падінні під час запису старий файл з даними не пошкоджується.
8. Тимчасові файли видаляються в блоці `finally`.

## Висновки
1. Створена гнучка ієрархія винятків у домені розумного будинку (IoT), яка дозволяє точно розділяти системні проблеми (проблеми файлової системи, синтаксичні помилки) та бізнес-відхилення (вихід показників сенсорів за нормальні рамки).
2. Застосування підходу **EAFP** у поєднанні з **Exception Chaining** (`raise ... from`) дозволило побудувати інформативний трейсбек, де низькорівнева помилка парсингу типу конвертується у зрозумілу користувачу помилку бізнес-валідації із збереженням першопричини.
3. Використання генераторів (`yield`) забезпечило потокову обробку великих файлів (I/O streaming). Завдяки цьому пам'ять ОЗП не перевантажується незалежно від обсягу вхідних даних (наприклад, при обробці мільйонів транзакцій чи записів сенсорів).
4. Кастомний контекстний менеджер `AtomicFileWriter` дозволив реалізувати принцип транзакційності на рівні файлової системи (атомарний запис), повністю нівелювавши ризик отримання пошкоджених файлів або втрати попередньої версії даних у разі раптового падіння програми під час запису.
